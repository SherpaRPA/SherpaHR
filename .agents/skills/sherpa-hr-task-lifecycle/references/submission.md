# Сдача задания

Сдача — передача результата проверяющему. Она не означает положительную оценку.
Issue закрывается после отчёта и уведомления; PR остаётся открытым.

## Итоговый отчёт

Открой PR из рабочей ветки в исходную ветку своего форка. В описании укажи
полный URL центральной issue в `SherpaRPA/SherpaHR`. Не используй команды
автозакрытия issue через merge.

Опубликуй в центральной issue итоговый отчёт о фактически выполненной работе:

```markdown
### FINAL REPORT — YYYY-MM-DD HH:MM:SS UTC
- Кандидат: <GitHub-логин или выданный идентификатор>.
- Версия задания: <SHA>.
- Форк / ветка / открытый PR: <URL и имя ветки>.
- Head SHA решения: <полный SHA>.
- Журнал промптов и действий: <ссылки, диапазон событий>.
- Что выполнено: <фактический результат>.
- Что не выполнено / известные ограничения: <список либо «нет»>.
- Выполненные проверки: <если были: команды, SHA, результаты, доступные ссылки>.
- Агент / модель / среда: <доступные фактические сведения>.
- Использованные инструменты / skills / MCP: <если применялись, ссылки на записи>.
```

Не выдавай неполную работу за полностью выполненную, а планируемую проверку
за состоявшуюся. После публикации прочитай отчёт по ID/URL.

## Review и обязательное упоминание

Если доступно, запроси review у `fxpw` в PR. Если запрос недоступен, укажи
причину и используй уведомление через issue. `fxpw` не может быть reviewer
собственного PR. При неопределённом ответе API проверь, появился ли запрос,
до повторной отправки. Не меняй права аккаунтов ради review request.

**В любом случае** опубликуй отдельный комментарий в центральной issue:

```markdown
@fxpw, задание сдано на проверку.

- PR: <полный URL>.
- Head SHA: <полный SHA>.
- Итоговый отчёт: <permalink комментария FINAL REPORT>.
- Ограничения: <нет / перечислить>.
- Review: <запрошен в PR / недоступен: причина; уведомление через эту issue>.
```

Прочитай сохранённый комментарий и проверь, что в нём есть `@fxpw`, ссылка
на PR, SHA и отчёт. Ссылка на этот шаблон не заменяет реальную публикацию.
Агент подтверждает сохранение комментария, а не доставку или прочтение
уведомления человеком.

## Закрытие

После публикации отчёта и упоминания:

1. Сверь текущий head PR с отчётом. Если версия изменилась, отрази актуальную
   работу и SHA в отчёте и уведомлении.
2. Закрой только свою центральную issue как «сдано на проверку», со ссылками
   на отчёт и уведомление. PR не мержи и не закрывай.
3. Прочитай состояние issue и PR. Сообщи кандидату ссылки, SHA и фактическое
   состояние: issue закрыта, PR открыт.

Если публикация недоступна, сохрани записи и сообщи о блокере. Без сохранённых
отчёта и упоминания не закрывай issue как сданную. Если недоступно только
закрытие, оставь отчёт/уведомление и сообщи, что issue остаётся открытой из-за
прав; не заявляй ложный статус CLOSED.

При доработке продолжай ту же issue и PR. Переоткрой свою issue, если доступно,
записывай новые промпты и каждое действие, обнови отчёт и повтори сдачу.
