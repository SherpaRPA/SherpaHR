# Design

## Context

`frontend/src/app.html` уже показывает `latest_comment.created_at` в UTC. Это абсолютное время ISO 8601, которого достаточно для вычисления давности на клиенте. Мотивация описана в `proposal.md`.

## Goals / Non-Goals

- **Цели:** детерминированное форматирование на границах интервалов; один момент отсчёта для всех строк одного обновления обзора.
- **Вне области:** менять UTC-формат, серверные правила просрочки, контракт API или добавлять фоновый опрос и поминутный таймер.

## Decisions

1. **Снимать текущее время браузера при каждой успешной загрузке или обновлении очереди**, включая обновление после сохранения комментария. Не использовать начальный `server_now`: без повторного получения он устаревает. Не вызывать часы отдельно для каждой строки, чтобы строки не разошлись на границе интервала.
2. **Форматировать чистой функцией с явным временем отсчёта.** Вычислять разницу абсолютных меток, не календарных дат. Проверять превышение 30 суток до округления, а остальные единицы считать по полным интервалам. Это исключает влияние часового пояса и перехода на летнее время и позволяет тестировать пороги без ожидания.
3. **В шаблоне добавить только подпись после `UTC`.** При отсутствии комментария весь блок по-прежнему скрыт. При непригодной метке времени не добавлять подпись с некорректной давностью.

## Risks / Trade-offs

- Расхождение часов браузера и сервера → небольшая погрешность подписей; время из будущего показывать как «менее минуты», не выводя отрицательные числа. Серверная классификация задач не меняется.
- Если обзор долго открыт без обновления, подпись остаётся снимком на момент его загрузки → пересчитывать при штатном обновлении, не вводя отдельный таймер.

## Migration Plan

Миграций нет. Изменение развёртывается и откатывается вместе с фронтендом.
