# Project Attention

## Purpose

Помочь руководителю заметить задачи, требующие вмешательства, и перейти от сигнала к обсуждению или изменению задачи без обхода проектов.

## ADDED Requirements

### Requirement: Область обзора
Система SHALL показывать «Требует внимания» при входе и смене демо-пользователя. Обзор MUST включать только незавершённые задачи активных проектов, в которых текущий пользователь одновременно руководитель и участник, независимо от исполнителя.

#### Scenario: Анна видит свои активные проекты
- **WHEN** Анна открывает обзор на свежих демо-данных при времени сервера, равном времени их создания
- **THEN** обзор включает заблокированные задачи №1 и №5, задачу №2 только с отметкой «Просрочена» и неназначенную №7, но не завершённые №3 и №9, архивную №10 и чужую №11.

#### Scenario: Другие роли
- **WHEN** пользователь переключается с Анны на Бориса или Веру
- **THEN** данные Анны исчезают; Борис видит пустой обзор, а Вера видит №11, но не задачи проектов, где она только участник.

#### Scenario: Запоздалые данные предыдущего пользователя
- **WHEN** запросы обзора и карточки Анны завершаются после переключения на Веру
- **THEN** обзор и карточка не показывают данные из этих запросов; экран продолжает отражать только состояние Веры.

### Requirement: Сигналы и порядок очереди
Система SHALL выводить одну строку на задачу с хотя бы одним сигналом: статус «Заблокирована», срок строго раньше текущего серверного времени UTC или отсутствие исполнителя. Строка MUST показывать все её сигналы. Группы сортируются по первому применимому сигналу в указанном порядке; внутри группы — ближайший срок первым, без срока в конце, затем ID по возрастанию.

#### Scenario: У задачи несколько сигналов
- **WHEN** незавершённая задача заблокирована и просрочена
- **THEN** она отображается один раз с отметками «Заблокирована» и «Просрочена» среди заблокированных задач.

#### Scenario: Срок ещё не истёк
- **WHEN** незаблокированная задача назначена и её срок совпадает с текущим временем либо отсутствует
- **THEN** она не появляется в очереди; если назначенный срок уже прошёл, появляется с отметкой «Просрочена».

### Requirement: Пояснение границ обзора
Обзор SHALL пояснять, что учитывает блокировки, просрочку и отсутствие исполнителя, но не просьбы, выраженные только в тексте. При успешной загрузке пустого списка система MUST сообщать об отсутствии задач с этими сигналами, а не об отсутствии любых проблем.

#### Scenario: Просьба только в обсуждении
- **WHEN** в проектах руководителя нет задач с формальными сигналами, но в обсуждении назначенной незаблокированной задачи с будущим сроком есть просьба о помощи
- **THEN** задача не попадает в очередь, а пустое состояние поясняет, какие сигналы проверены и что просьбы только в тексте не учитываются.

### Requirement: Контекст и переход к действию
Строка MUST показывать задачу, проект, исполнителя или его отсутствие, срок и, при наличии, краткий фрагмент последнего комментария с автором. Фрагмент SHALL обозначаться как последний комментарий, не как причина сигнала. Из строки SHALL открываться обычная карточка с полной перепиской и действиями, разрешёнными в проекте этой задачи.

#### Scenario: Разбор задачи из другого проекта
- **WHEN** Анна открывает №7 из обзора, где также есть задачи проекта №1
- **THEN** она видит полное обсуждение №7 и может выбрать исполнителя только среди участников проекта №2 или снять назначение.

#### Scenario: Сигнал исчезает после правки
- **WHEN** Анна назначает исполнителя задаче №7, у которой нет других сигналов
- **THEN** после сохранения задача исчезает из очереди без перезагрузки страницы, а открытая карточка остаётся доступной.

### Requirement: Сохранение комментариев
Карточка активного проекта SHALL сохранять непустой комментарий до 5000 байт UTF-8 от текущего участника. API MUST вернуть `201` и сохранённый комментарий с автором и временем UTC, не увеличивая версию полей задачи. Новый комментарий SHALL появляться в обсуждении без потери несохранённых полей задачи и сохраняться при повторном открытии.

#### Scenario: Ответ из карточки
- **WHEN** участник отправляет корректный комментарий
- **THEN** ответ появляется в карточке и при повторном чтении, а в обзоре отражается новый последний комментарий, если задача остаётся в очереди.

#### Scenario: Комментарий сохранён, обзор не обновился
- **WHEN** комментарий из обзора успешно сохранён, но следующий `GET /api/attention` не удался
- **THEN** комментарий остаётся виден в карточке, ошибка относится только к обновлению очереди, а кнопка повтора заново читает очередь, не отправляя комментарий повторно.

#### Scenario: Ограничения записи
- **WHEN** API получает пустой или превышающий лимит текст, либо попытку комментировать архивную или недоступную задачу
- **THEN** API соответственно возвращает `422`, `409` для архива или `404` для недоступной задачи и ничего не сохраняет.

### Requirement: Полнота списка проекта
Список задач доступного проекта SHALL включать задачи без исполнителя наряду с назначенными. Существующие ограничения чтения и записи MUST сохраняться.

#### Scenario: Неназначенная задача в проекте
- **WHEN** Анна открывает список задач проекта №2
- **THEN** видит задачу №7 с отметкой «Не назначен» и может открыть её карточку из этого списка.

### Requirement: Сохранение рабочего режима проекта
Режим проекта SHALL оставаться доступным из навигации. Участники активного проекта MUST по-прежнему создавать и редактировать задачи, искать их по названию и фильтровать по статусу. Архив MUST оставаться доступным участникам только для чтения; чужие проекты и задачи MUST оставаться недоступными.

#### Scenario: Участник работает с задачами вне обзора
- **WHEN** Борис как участник активного проекта №2 открывает его из навигации, создаёт задачу и меняет её статус
- **THEN** задача и изменения видны после повторного открытия, а поиск по названию и фильтр статуса по-прежнему ограничивают список условиями пользователя.

#### Scenario: История архива доступна без записи
- **WHEN** Анна открывает архивный проект №4 и карточку его задачи №10
- **THEN** список, поля задачи и обсуждение доступны для чтения, а действия создания, изменения и комментирования недоступны в интерфейсе; прямые запросы записи получают `409`.

#### Scenario: Прямое обращение к чужому объекту
- **WHEN** Анна запрашивает список или создание задач в проекте №5, либо чтение, изменение или комментирование задачи №11
- **THEN** API возвращает `404` без данных чужих объектов и ничего не сохраняет.
