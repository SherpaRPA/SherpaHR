# Design

## Context

`GET /api/attention` уже выбирает одну запись комментария по существующему порядку (`id DESC`), но в `latest_comment` отдаёт только `author` и `excerpt`. У выбранной записи уже есть `created_at` в UTC. Angular использует `DatePipe` с явной зоной `UTC` для других дат.

## Goals / Non-Goals

**Goals:** передать время выбранного комментария из API во фронтенд без дополнительного запроса и отобразить его независимо от зоны браузера.

**Non-Goals:** менять схему БД, порядок выбора комментария, правила очереди или отображение обсуждения в карточке.

## Decisions

- В существующем запросе выбирать `c.created_at` вместе с текстом и возвращать его в `latest_comment.created_at` в исходном формате ISO 8601 UTC. Не добавлять поле в корень строки. Если комментария нет, сохранять `latest_comment: null`. Это исключает отдельный запрос и гарантирует, что время относится к тому же комментарию, что автор и фрагмент.
- Расширить `AttentionTask.latest_comment` обязательным полем `created_at` для непустого объекта. В шаблоне обзора использовать `DatePipe` с форматом `d.MM.yyyy HH:mm` и часовым поясом `UTC`; суффикс `UTC` и разделитель ` · ` вывести отдельно, курсив оставить только на фрагменте. Форматирование на фронтенде сохраняет машиночитаемое значение API.

## Risks / Trade-offs

- Использование локального времени браузера или шаблона `dd` нарушит ожидаемый формат; проверять отображение для однозначного дня в зоне, отличной от UTC.
- Обновлённому фронтенду нужно новое поле API. При раздельном развёртывании сначала обновить бэкенд: старый фронтенд игнорирует дополнительное поле. Миграция данных не нужна.
