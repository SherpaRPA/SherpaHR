# SherpaHR — тестовое задание

Задание: [task_v6.md](task_v6.md).
Файл импорта: [import example (2).xlsx](<import example (2).xlsx>).

Агента, модель, редактор, инструменты и способ выполнения кандидат выбирает
самостоятельно. Сессия или доступ от организатора не требуются.

## Журнал работы

Передайте агенту [AGENTS.md](AGENTS.md) и
[скил отчётности](.agents/skills/sherpa-hr-task-lifecycle/SKILL.md).
Агент создаёт одну issue в
[SherpaRPA/SherpaHR](https://github.com/SherpaRPA/SherpaHR/issues)
по шаблону «Выполнение тестового задания» и ведёт в ней журнал всей работы:

- Каждый пользовательский промпт и уточнение — полностью, по порядку.
- Каждое действие агента — время, что выполнено, входные данные и результат.
- Фактические агент и модель, использованные инструменты, skills и MCP —
  если они применялись; недоступные сведения отмечаются явно.
- Ошибки, повторные действия, изменения файлов и выполненные проверки —
  с результатами и ссылками, если они доступны.

Правила записи: [journal.md](.agents/skills/sherpa-hr-task-lifecycle/references/journal.md).
Не публикуйте секреты, настройки авторизации и персональные данные.

## Репозиторий решения

Работа выполняется в отдельной ветке публичного форка кандидата. PR открывается
в этом форке, из рабочей ветки в исходную ветку форка. Центральная issue
остаётся в SherpaRPA/SherpaHR; решение в основную ветку SherpaHR не отправляется.

Исходный `.gitignore` разрешает только комплект задания. В своём форке добавьте
пути файлов решения в секцию `CANDIDATE SOLUTION` перед последними исключениями.

## Сдача

Агент открывает PR, публикует итоговый отчёт и комментарий с обязательным
`@fxpw` в центральной issue. Если GitHub позволяет, дополнительно запрашивает
review у `fxpw` в PR; иначе указывает, что уведомление сделано через issue.
После проверки публикации закрывает свою issue как «сдано на проверку».
PR остаётся открытым. Оценку выполняет проверяющий.

Формат отчёта и порядок передачи:
[submission.md](.agents/skills/sherpa-hr-task-lifecycle/references/submission.md).
