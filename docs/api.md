# API существующего приложения

Ответ: `{"data": ...}`; ошибка: `{"error": "описание"}` с соответствующим
HTTP-статусом. JSON UTF-8. Заголовок `X-Demo-User: 1` выбирает Анну,
`2` — Бориса, `3` — Веру. По умолчанию 1. Это открытый демо-переключатель,
не доказательство личности; локальный API не предназначен для публикации в сеть.

| Метод и путь | Текущее поведение |
|---|---|
| `GET /api/health` | Проверка запуска сервиса |
| `GET /api/context` | Демо-пользователи, выбранный пользователь, время UTC и дата создания демо |
| `GET /api/projects` | Только проекты текущего пользователя, участники и количество задач |
| `GET /api/attention` | Задачи с формальными сигналами в активных проектах руководителя |
| `GET /api/projects/{id}/tasks` | Все задачи доступного проекта |
| `POST /api/projects/{id}/tasks` | Создать задачу в активном проекте |
| `GET /api/tasks/{id}` | Доступная задача с комментариями и авторами |
| `PATCH /api/tasks/{id}` | Изменить поля с проверкой версии |
| `POST /api/tasks/{id}/comments` | Сохранить комментарий в активном проекте, вернуть 201 |

Поля задачи для создания и изменения: `title`, `description`, `status`,
`assignee_id`, `due_at`. При создании `title` обязателен. Неизвестные поля
отклоняются. Исполнитель — участник проекта или `null`. Даты — строго
`YYYY-MM-DDTHH:mm:ssZ` либо `null`; текущий UI редактирует их с точностью до минуты.
Для PATCH обязательно целое поле `version`, полученное при чтении.
Успешное изменение увеличивает версию; устаревшая версия возвращает 409.
Метод добавления комментария принимает `{"body":"текст"}`. Текст не должен быть пустым.
Ответ `201` содержит `id`, `task_id`, `user_id`, `body`, `created_at` (UTC) и
`author`. Комментарий доступен в деталях задачи; версия задачи не меняется.

Максимумы строк в байтах UTF-8: название 200, описание 10000, комментарий 5000.
Максимум тела изменения — 32 KiB. Ошибка валидации — 422, JSON — 400,
неизвестный пользователь — 401, отсутствующий или недоступный объект — 404,
запись в архив — 409. Поиск и фильтр статуса в текущем UI выполняются локально.

## Требует внимания

`GET /api/attention` возвращает `data` со списком задач из активных проектов,
где текущий пользователь одновременно руководитель и участник. Задачи со
статусом `done` исключены. Каждая строка содержит `id`, `title`, `project_id`,
`project_name`, `assignee_id`, `due_at`, `reasons` и `latest_comment`.

`reasons` содержит все применимые коды в порядке `blocked`, `overdue`,
`unassigned`. Просрочка означает срок строго раньше серверного времени UTC
на момент запроса. Каждая задача встречается один раз. Порядок ответа API —
сначала по первому коду, затем по возрастанию срока (без срока в конце), затем по `id`.
`latest_comment` — `null`, если комментариев нет, или объект с `author`,
`created_at` (время создания в ISO 8601 UTC) и `excerpt` (до 160 символов
Unicode и многоточие при обрезке). Все три поля относятся к комментарию
с максимальным `id`; в корне строки поля `created_at` нет.
Текст обсуждения не влияет на сигналы.

В интерфейсе очередь «Требует внимания» по умолчанию показывает задачи с
самыми свежими последними комментариями первыми. При равном `created_at`
сохраняется порядок API. Задачи без комментариев идут после остальных и
между собой тоже сохраняют порядок API. Кнопка сортировки рядом с «Обновить»
переключает отображение на порядок ответа API («по сигналам») и обратно.
Переключение не запрашивает данные повторно; при обновлении очереди выбранный
режим применяется к свежему ответу.
